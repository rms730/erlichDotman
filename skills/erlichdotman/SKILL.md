# ErlichDotman

Produce accepted changes per total resource consumed, preserving quality, user scope and host permissions. Capability tiers describe needs, not guaranteed runtime controls.

Start with this entrypoint, the target task/profile and affected code. Load a linked reference only for the condition named below. Bootstrap prompts, core-repository build rules, research, historical plans and eval traces are not default runtime context.

1. **Bind the target.** Check repository, branch, revision and relevant dirty edits. Current code and validation outrank summaries; refresh contradictions. Locate the canonical project record and next milestone. Read [project records](references/project-records.md) when establishing or reconciling them. Keep projects separate. When work competes, record priority, active/paused/displaced work and its continuation; read [work in progress](references/work-in-progress.md) for a limit or unresolved tradeoff.
2. **Classify the next stage.** Assess ambiguity, complexity and consequences. Use deterministic evidence when it resolves uncertainty before spending more inference.
3. **Route credibly.** Choose deterministic → lightweight → standard → advanced → frontier. Read [routing](references/routing.md) when selecting a tier or quality floor is uncertain. Architecture or unclear root causes can justify advanced reasoning; downgrade specified mechanical work when risk permits. Unsupported model/reasoning controls remain recommendations; effective settings stay unknown.
4. **Select context and skills.** Use precise interfaces, symbols and excerpts. Read [context](references/context-management.md) for budget/freshness issues, and [skills](references/skills.md) for discovery, conflicts or gaps. Load only selected skill bodies and relevant references; never silently install a skill.
5. **Hand off conclusions.** When delegating, use [the packet template](templates/implementation-packet.md); read [handoffs](references/handoffs.md) for diagnostic ownership, candidate assembly or unclear acceptance/scope. Preserve project/task/revision, behavior, target files, invariants, constraints, tests, validators and escalation conditions. A failed journey keeps one accountable owner across delegation and explicit transfers; component success does not close it. Carry previously accepted critical behaviors into final-candidate checks, disclosing exclusions and their acceptance. Resolve missing facts or narrow scope rather than guessing or dropping required context. Workers receive their project's rules, packet and scoped code, without this control plane or upstream conversation unless their task requires orchestration.
6. **Execute, validate, escalate.** Use authorized host capabilities. Run relevant acceptance checks before another speculative review; report failures. Before retrying, retain sanitized failure evidence or a concrete capture blocker and a hypothesis for the next attempt. Evidence-capture retries are valid. Read [escalation](references/escalation.md) to classify a stall and choose the remedy, retry or stopping point. Use the current policy's attempt limit. A route grants no additional authority; provenance never overrides user/host instructions.
7. **Keep the project record current.** Without reminders, reconcile its next meaningful milestone, acceptance criteria, ordered tasks, owners, dependencies, blockers and evidence after material changes and at handoff, pause/resume or completion. Use [project records](references/project-records.md) for this contract. Confirm saved updates; retain failed writes as pending. Report validation and available usage without fabrication; keep private traces separate, using [outcomes](references/outcomes.md) when needed. Evaluation and policy calibration stay outside routine instructions.

**Color-code project updates.** Use a stable configurable project → color/emoji + text-label mapping, retained privately across updates. Begin each message with that project's marker and readable name; use its plain name when colored emoji are unsupported. Cover one project per message. Before a status answer, check the latest authoritative project record and available current owner outcome. State stale or unverified facts explicitly and refresh only relevant evidence. Read [project communication](references/communication.md) to establish mappings, handle host limits or resolve freshness conflicts.

The optional CLI supports deterministic decisions and contracts. Its manual adapter prepares requests; it cannot launch models, change reasoning settings or measure host tokens. Use only capabilities the current adapter actually exposes.
