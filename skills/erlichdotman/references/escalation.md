# Escalation

Before more inference, run the deterministic check likely to resolve uncertainty. Before repeating a failure, preserve sanitized failure evidence or a concrete capture blocker and a hypothesis explaining what the next attempt will establish. A bounded retry to capture missing evidence is legitimate. Transport success, an empty result and passing component tests do not establish an application outcome.

Classify the stall before escalating: ownership needs one accountable owner; tooling/access needs capture or access repair; context needs targeted expansion; implementation needs a hypothesis and regression check; reasoning may need stronger debugging. Do not treat every stall as a model problem. Classification is a judgment, not something the checker infers from a log. Preserve quality floors and attempt limits.

Record completed implementation attempts, requested versus effective tier, validators and failure evidence. Read the active policy's attempt limit; do not infer it from a historical plan. Under the legacy heuristic, a failed implementation raises the tier. With a supplied classified retry sidecar, only implementation/reasoning failure raises it automatically; capture retries do not. Reasoning stalls still preserve the advanced floor, and frontier failure remains bounded. At exhaustion report the evidence and required decision. Do not restart the count under a new task ID, or label a diagnostic collection as a completed implementation merely to populate a counter. Unknown effective settings and usage stay unknown.

Permissions are independent: stop before unauthorized destructive changes, installation or public publication. Existing user authorization persists. A stronger model never grants broader authority.
