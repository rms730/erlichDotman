# Escalation

Before more inference, run the deterministic check likely to resolve uncertainty. A known compiler/type error can be mechanical. An unclear root cause, conflicting evidence or recurrent failure warrants stronger debugging. Missing context warrants targeted expansion before automatically buying more capability.

Record completed attempts, attempted/effective tier, validators and failure evidence. Use a finite limit (bootstrap: three implementation attempts). A failed attempt escalates above its previous tier; frontier failure is still bounded. At exhaustion report the evidence and required human decision. Do not restart the count under a new task ID.

Permissions are independent: stop before unauthorized destructive changes, installation or public publication. Ask only for the necessary action and explain the actual boundary. Existing user authorization persists. A stronger model never grants broader authority.
