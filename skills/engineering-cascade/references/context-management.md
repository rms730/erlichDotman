# Context

A profile contains project ID, repository/branch/revision, stack, compact architecture, conventions, objectives, constraints, decisions, validators and skill locations. Store private profiles outside public artifacts. Refresh from repository truth after interface changes; HEAD alone cannot detect dirty files.

An excerpt manifest records item ID, project/revision, path/symbol, content, provenance, estimate and whether it is required. Include relevant interfaces, invariants and tests before optional examples/history. Required context that exceeds the budget stops dispatch; expand or narrow scope. Never silently truncate.

Use a runtime tokenizer when available; otherwise label rough estimates. Context estimates are neither billed tokens nor a provider context guarantee. Reserve room for skills, packet prose, tool output and response. Reject mixed/stale items even if they would be omitted.

When the user requests reuse of another project's generic architectural pattern, verify and restate it as facts and constraints of the target project. Keep the source project's private history out of the worker's context. Budget limits govern dispatch; independent preparation can continue while missing facts or a budget gap are resolved.
