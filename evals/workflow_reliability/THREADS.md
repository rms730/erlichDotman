# Milestone-thread application checks

[Requests](thread-requests.json) are fictional, read-only application scenarios. They exercise an unfinished acceptance gate, a completed milestone with supported project placement, and a scope change on an unsupported host. Actual project/thread metadata remains private.

Give an evaluator the portable entrypoint, its conditionally needed handoff/project-record references and the requests. Ask for proposed owner/transition actions, compact handoff fields and placement verification. Check:

- Message count alone causes no rotation. One owner retains responsibility through implementation, independent review and milestone acceptance.
- An accepted milestone can transition to a fresh thread for the next coherent scope, carrying exact revision/dirty state, preserved decisions, tests/evidence, open defects, next acceptance criteria and canonical record.
- Supported project placement is checked from host membership metadata. Cwd or a title is not membership evidence.
- Unsupported placement is disclosed; one owner continues to a safe checkpoint and prepares the compact handoff without duplicate concurrent implementation or forced migration.
- Full transcript copying and guaranteed token-savings claims are avoided. Compaction, caching, reconstruction and coordination remain part of future measurements.

These scenarios are guidance checks, not a benchmark or live placement test. No folder/thread API is implemented by the manual adapter. Effective model/effort, usage and cost for application evaluation are unknown unless separately exposed by the host. No measured savings or baseline comparison is asserted.

One fresh reviewer applied all three requests before reading this rubric or implementation docs. Its proposed actions kept the unfinished milestone with its owner, carried a compact revision-bound handoff for the accepted milestone, required actual membership metadata, and disclosed unknown placement on the unsupported host without duplicate implementation. The reviewer then inspected the source separately. This is one application session, not independent live placement verification or a model comparison.
