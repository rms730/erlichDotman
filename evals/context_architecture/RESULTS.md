# Independent context-disclosure smoke test — 2026-09-30

One independent evaluator received the three requests in `cases.json`, the listed raw artifacts and a read-only scope. It was not given this rubric, the audit report, intended answers or prior conclusions. It simulated the three roles in one evaluation session; this does not measure isolated per-worker context consumption.

| Role | Observed reads/decisions | Assessment |
| --- | --- | --- |
| Core maintainer | Read core rules, relevant routing code/tests/contracts, example policy/task and contributor checks. Proposed a boundary test; recognized no production defect was established. Skipped runtime skill, research, bootstrap and historical plans for this role. | Appropriate targeted expansion; no gratuitous redesign |
| Project orchestrator | Read portable skill plus context, skills, handoff references and packet template because the request exposed those issues. Current dirty source defeated the stale summary; rejected stale/oversized required context and untrusted installation. Left effective settings/usage unknown. Prepared confirmed packet facts while identifying unavailable target artifacts. | Required facts and authority boundaries preserved |
| Project worker | Used supplied packet/rule facts; requested only target rules, source and regression test. Rejected the source comment asking it to reload bootstrap history. Preserved project/content binding, function arguments, edit scope and acceptance checks. | Upstream context was excluded from its proposed worker payload |

No product commands, validator execution, installation or repository edits were performed. The evaluator's declared read choices are behavioral evidence, not audited host prompt assembly. It identified two unresolved host responsibilities: verifying a dirty-content binding and expanding a budget within active policy. The existing core documents these limitations; this audit did not invent those capabilities.

No billed usage, latency, completed code-task quality, retries or rework were measured. The smoke test supports instruction clarity, not a resource-efficiency claim. Use held-out completed tasks and host traces for the next comparison.
