# Roadmap

1. **Make the evidence complete.** Capture compact stage outcomes on the next already-authorized task, including binding, requested versus observed capability, retries, available usage, elapsed time and human minutes. Audit missing legs and logging overhead before building a provider integration. Keep unavailable measurements `null`.
2. **Run an exploratory orchestration pilot.** Preregister eight held-out tasks in four matched pairs. Freeze the baseline, acceptance, tools, other skills, model settings and retry limits; randomize assignment/order and use an independent blinded acceptance review. Include failed/incomplete work and seven-day rework. This tests the evaluation process and orchestration/context effects, not general savings or cheaper-model routing.
3. **Add only the runtime integration the evidence needs.** After observing one real host trace, implement an opt-in adapter or collector for capabilities the host actually exposes. Test observed effective settings, incremental usage and missing measurements. Do not synthesize unavailable controls or billing from account-wide counters.
4. **Evaluate routing and handoffs separately.** With reliable capture, compare fixed capability policies against stage-specific routing on a larger held-out set. Test compressed packets and dirty-tree fingerprints against observed omission/staleness failures. Use quality, total resources and later rework together before proposing policy changes.

The [implementation priorities and exit criteria](IMPROVEMENT_PLAN.md) and [pilot kit](../evals/pilot/README.md) make these steps concrete. Pages can show concise dated status linked to repository evidence; they do not replace technical records or become runtime context. These documents are loaded for explicit evaluation/improvement work only.

Later, only if evidence justifies it: SWE-bench runner integration, trusted skill-source recommendations, host-specific discovery adapters, durable scheduling across projects, availability fallback, price catalogs and learned expected-total-cost models. No opaque self-modification, silent installations or unmeasured savings claims.
